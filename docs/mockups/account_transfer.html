Recommendation

Phase 1: a transfer code

Small, needs no plugins, stores nothing personal, and works between Android and iPhone. Ship it with or soon after the server switch.

Phase 2: Apple and Google sign-in

For a lost or broken phone. Ship it before a public release, together with "Delete my account", because that is when the store rules start to apply.

What counts as progress

On the new server everything a player owns is stored under their player id. A transfer doesn't copy anything: the new phone simply becomes that player, so it all moves at once.

Moves

  • Diamonds, the ledger and unclaimed prizes
  • Gold, owned and worn cosmetics (the server's save)
  • Premium items bought with diamonds
  • Best scores, rooms reached, runs on the boards
  • Milestones, ladder steps, the 7-day streak
  • Today's Daily Run tries (still counted, not reset)
  • Leaderboard name and flyer
  • Synced settings

Stays on each phone

  • This phone's own switches (Profile.LOCAL_KEYS)
  • Push alerts: the new phone registers its own token
  • Your runs (user://runs.json), unless we add an upload later

Never merged

If the new phone already has progress of its own, it is replaced, not added. Merging would let one person farm diamonds and prizes on several accounts and pour them into one.

Server: endpoints and data

EndpointWhoDoes
POST /v1/transfer/createold phone, signed inMakes a 12-character code (Crockford base32, 60 bits), valid 24 h, single use. Cancels any earlier unused code. Answers {code, expires_at}. At most 5 a day per player.
POST /v1/transfer/cancelold phoneCancels its open code.
POST /v1/transfer/previewnew phone, signed in{code} to a summary for screen 5: name, best score, gold, diamonds, item count. Counts as a try.
POST /v1/transfer/redeemnew phone{code, device_key}. In one transaction: marks the code used, revokes every session and device key of the old phone, enrols the new device key, answers a session for that player. The new phone's own anonymous player is left behind.
any call from the old phoneold phone401 {"error": "account_moved"}. The client shows screen 6, then signs up as a new player.

transfer_codes

code_hash (sha-256, the code itself is never stored), player_id, created_at, expires_at, used_at, used_by_ip.

device_keys and sessions

Each key and refresh token belongs to a player and can be revoked. A redeem revokes all of them for that player.

transfer_attempts

Per device and IP, for the rate limits; kept 7 days.

transfer_log

Who moved when, from which player id. It shows what happened when a player says "my progress is gone".

Conflicts

One phone per account

A transfer moves the account; it never shares it. After a redeem only the new phone is that player, so two phones can't write to one account at once.

Two phones type the same code

The first redeem wins inside its transaction; the second gets "That code was already used".

The old phone keeps playing

Screen 3 sends queued runs and the save before it shows the code. Anything played after that on the old phone is lost once the code is used; screen 3 says so.

The new phone has its own progress

Screen 5 shows both sides and replaces, never merges. The left-behind player keeps its runs on the boards, like any player who stopped playing.

Moving back

Works the same way: the new phone makes a code and the old phone types it. Daily Run tries and prizes stay with the player, so a move never resets them.

Abuse cases

CaseGuard
Guessing codes60 bits per code, valid 24 h and once. A redeem or preview counts as a try: 5 tries per device per hour, 20 per IP per hour, then a 1-hour block. Guessing would take more tries than all players together are allowed in years.
Stealing a code ("send me your code for free diamonds")The warning on screen 3; codes never go in links, push messages or logs; a player can cancel a code; screen 5 shows what moves before anything happens.
Farming prizes on many accounts and merging themNo merge: a transfer replaces. Diamonds can't be moved between players.
Spamming code creation5 codes a day per player; a new code cancels the old one.
Resetting Daily Run tries by movingTries belong to the player, so they move along.
Selling accountsPossible, as in most games. Everything is cosmetic, so the payoff is small; not worth blocking.
Replaying an intercepted redeemHTTPS only; the code is single use and the redeem is one transaction.
