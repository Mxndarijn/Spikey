Duel mode

A 1v1, best of three rounds. Each round both players fly the same map at the same time and see each other as a see-through rival bird. Only taps travel over the network; each phone rebuilds the rival exactly with the deterministic sim, and the server judges. Text copy: docs/DUEL_MODE.md.

Plan only · waiting on your answers No sim change, no gameplay-version bump Cosmetic-only monetization kept Phase 1: ghost duel · Phase 2: realtime

1. Game rules

A Duel round is a normal run: GameSim(seed, season) with the server's seed and no revives. Everything below is about how two such runs are compared.

MapA new server seed each round, sent only at the countdown (like the Daily Run seed). Same seed and season for both.Nobody can practise the map; three rounds are three maps.

2. Seeing each other live

What is sent

Every 100 ms (6 ticks) each phone sends "I am at tick T, and these are my taps since last time". The "no taps up to T" part is what lets the other phone step the rival safely up to T.

u8 type · varint T · u8 n · n × varint tap delta

Bandwidth

  • Payload: 10 msg/s × about 6 B = 60 B/s
  • With WebSocket, TLS and TCP/IP: about 0.9 KB/s, 7 kbit/s each way
  • A 4-minute round: about 30 KB payload, about 220 KB on the wire
  • Server: about 4 KB/s per live match

Your bird is never delayed

Your sim runs on your phone at 60 Hz exactly as today. Only the rival is drawn a little in the past, at my_tick − D.

When rival data is…What you seeWhat the phone does
within the bufferA smooth rival birdSteps the rival sim exactly with the confirmed taps. D drifts slowly by playing the rival at 0.95× or 1.05× for a moment, never a jump.
late, up to 0.5 sStill smooth, maybe a small easeSteps a copy (SimCopy) guessing no tap. When the real taps come, the copy is dropped, the rival sim steps on exactly from its last confirmed state, and the drawn bird eases to the true spot over 6 frames. A guessed crash is never shown.
0.5 to 5 s lateRival fades to 25% with a connection iconGrows D so it plays smoothly again once data comes back.
over 5 s"Mira is reconnecting"Your round goes on; the server's rejoin rules decide (section 3).

Drawing the rival without touching your sim

services/duel_link.gd

The WebSocketPeer, encodes and decodes tick batches. Uses only sim/ and meta/.

meta/duel_rules.gd

Best of three, the S + 1 clinch, ties, time limit. Pure rules like DailyRunRules; the server has the same rules in Rust, held together by shared fixtures.

game/duel/rival_driver.gd

Owns a second GameSim, steps it only from DuelLink's taps (as the replay driver does for Watch), holds the jitter buffer and the guess-and-correct copy.

game/duel/rival_view.gd

A BirdView in the rival's look at 45%, name tag, WILD tag, crash puff. Draws no room and no hazards; your RoomView stays yours. No sounds but a soft crash.

sim/ does not change; it already runs many sims side by side (bots, SurvivalSearch). Your RunController and its sim are untouched; game/ writes to neither sim. test_layers.gd holds as it is.

3. Network and server

Transport

  • wss://api.<domain>/v1/duel/ws, axum WebSockets; Traefik passes them through
  • Sign-in: the HTTP API's access token in the first message
  • Godot's built-in WebSocketPeer, Android and iOS
  • One tokio task per match holds both players' Rust sims
  • One replica for now; more later need sticky routing by match id
  • Each round's seeds, taps and result go to Postgres (duel_matches, duel_rounds)

Matchmaking

  • Invite code or link (phase 1 and 2): 6 letters with no look-alikes, https://<domain>/duel/ABC123 opens the app; 10 minutes
  • Random queue (phase 2): same gameplay version, then a hidden Glicko-2 Duel rating whose range widens every 5 s. Nobody after 30 s: offer a ghost duel against a recent verified run
  • Friends (later): needs stable accounts, Apple and Google sign-in from the phone-transfer plan

Rejoin and forfeit

  • In a round your bird keeps flying; taps within 5 s of the server's clock count. Past 5 s: a crash at the last confirmed tick
  • Back within 30 s: you play the next round
  • Between rounds: 30 s to return, else the match is forfeited
  • Leave = forfeit; 3 forfeits a day = 10 minutes out of the queue
  • Server restart: matches in play end with no result; deploys wait for live matches (10 minutes at most)

Anti-cheat: the server judges

  • The server steps both sims from the taps; phones never report the result
  • Clock check: ticks must follow the server clock since the countdown within 5 s. Stops playing a hard room in slow motion, the one cheat realtime adds
  • Taps ascending, one a tick at most, 20000 a round at most
  • A disagreement goes to the headless Godot check, as today
  • Perfect bots: plausibility checks into a review queue; no money at stake

Needed from the server move first

Phase 1 uses only HTTP ops: 3 Daily-Run-style functions would work on Supabase today, but building them once on the new server after the cutover is the recommendation. Phase 2 needs the new server live (rollout step 5): its sessions and device-key sign-in, the Rust sim in the server (built on the branch), the versioned verifier (sim_g24, …), the 426 "please update" answer, WebSockets through the ingress. Supabase can't host the realtime part.

6. Phased rollout

Phase 1 · about 1.5–2 weeks

Ghost duel (async)

  • The challenger plays three rounds on three server seeds, verified like any run, and sends a code or link
  • The rival plays each seed with the challenger's verified run drawn as the rival bird (the replay driver, stepped in step with their own tick). Decided at two wins
  • The challenger gets a push and watches each round with both birds
  • Server: 3 ops (create_duel, get_duel, submit_duel_round), 2 tables, the submit_daily_run checks. Fits today's backend too
  • Most phase 2 client code (rival view, rules, screens) lands here
Phase 2 · about 4–5 weeks

Realtime

  • Server WebSocket, match actor, queue, rating, rejoin: 1.5–2 weeks
  • Client DuelLink, jitter buffer, guess-and-correct, live screens: 1.5 weeks
  • Tests: two headless Godot clients over loopback with added delay, loss and reorder; bots playing whole matches against the server; shared fixtures for GDScript and Rust rules: 1 week
  • After the server cutover only
Later

Friends and a Duel board

  • Friends list once accounts are stable (Apple and Google sign-in)
  • Maybe a weekly Duel board with small diamond prizes, like Today
